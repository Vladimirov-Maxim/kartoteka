# Кухонная картотека

Картотека блюд со свайп-рандомайзером. Не знаешь, что готовить — свайпаешь карточки:
вправо открывается рецепт с кнопкой «Готовить», влево показывается следующее блюдо.

База общая: двое заходят под своими аккаунтами, видят один список, изменения
появляются друг у друга сразу.

- **Страница** — статика, лежит на GitHub Pages. Никакого своего кода на сервере.
- **Данные** — Postgres в Supabase. API он делает сам из таблиц.
- **Фильтры, поиск, колода** — считаются в браузере: при открытии список
  загружается целиком и дальше работает без запросов, в том числе без сети.

---

## Быстрый старт

Полчаса, из них двадцать минут — тыкать кнопки в веб-панелях.

### 1. Проект в Supabase

1. Зайти на [supabase.com](https://supabase.com), войти через GitHub.
2. **New project** → название любое, регион ближе к себе, пароль базы придумать
   и никуда не записывать (он нам не понадобится).
3. Дождаться, пока проект поднимется — минуты две.

### 2. Создать таблицы

1. В проекте слева **SQL Editor** → **New query**.
2. Открыть файл `supabase/schema.sql` из этого репозитория, скопировать целиком,
   вставить в окно, нажать **Run**.
3. Внизу должно появиться `Success. No rows returned`.

Вникать в SQL не нужно, но если интересно — там четыре таблицы (кухни, участники,
блюда, журнал готовки) и правила доступа: строку видно, только если ты состоишь
в той же кухне. Проверка живёт в базе, а не в коде страницы, поэтому её нельзя
обойти, поправив JS в браузере.

### 3. Выключить подтверждение почты

Иначе после регистрации придётся лезть в ящик за письмом.

**Authentication** → **Sign In / Providers** → **Email** → выключить
**Confirm email** → **Save**.

Если оставить включённым — тоже работает, просто регистрация станет двухшаговой.

### 4. Прописать ключи

**Settings** (шестерёнка) → **API**. Оттуда нужны две строчки:

| В панели Supabase | Куда положить |
|---|---|
| Project URL | `SUPABASE_URL` |
| anon public | `SUPABASE_ANON_KEY` |

Открыть `config.js` и вставить:

```js
export const SUPABASE_URL = "https://xxxxxxxxxxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGci...";
```

Ключ `anon` **публичный по замыслу** — сам по себе он не даёт доступа к данным,
всё закрыто правилами внутри базы. Поэтому файл спокойно лежит в открытом
репозитории. Единственное, что нельзя выкладывать — это ключ `service_role`
с той же страницы; он обходит все правила, и в приложении он не нужен.

### 5. Выложить на GitHub Pages

Создать на GitHub пустой публичный репозиторий `kartoteka` — без README,
без .gitignore, совсем пустой. Дальше из папки проекта:

```bash
git init -b main
git add .
git commit -m "Кухонная картотека"
git remote add origin https://github.com/Vladimirov-Maxim/kartoteka.git
git push -u origin main
```

Затем в репозитории: **Settings** → **Pages** → **Source: Deploy from a branch** →
ветка `main`, папка `/ (root)` → **Save**.

Через минуту приложение открывается по адресу
`https://vladimirov-maxim.github.io/kartoteka/`

На бесплатном тарифе Pages работает только из **публичного** репозитория.
Для нас это нормально: секретов в коде нет. Если хочется приватный —
тот же самый набор файлов без изменений разворачивается на Cloudflare Pages
или Netlify.

### 6. Завести кухню и позвать напарника

1. Открыть ссылку, зарегистрироваться по почте и паролю.
2. Нажать **Создать кухню**.
3. Вкладка **Блюда** → там будет **код приглашения** из шести символов.
4. Второй человек открывает ту же ссылку, регистрируется под **своей** почтой
   и вводит этот код. Всё, вы в одном списке.

На телефоне: открыть ссылку в браузере → «Добавить на экран «Домой»».
Дальше открывается как обычное приложение, без адресной строки.

## Как хранятся данные

**Postgres в Supabase** — источник правды. Четыре таблицы:

- `kitchens` — общее пространство и код приглашения;
- `members` — кто в нём состоит;
- `dishes` — блюда;
- `cook_log` — журнал готовки: одна строка на каждое нажатие «Готовить».

Журнал сделан отдельной таблицей не просто так. Если хранить у блюда счётчик,
двое, нажавшие «Готовить» одновременно, затрут отметку друг друга. Записи в
журнал только добавляются, поэтому конфликтовать там нечему, а «когда готовили
последний раз» и «сколько раз всего» считаются из него на лету. Бонусом видно,
кто готовил.

**Браузер** держит копию базы в `localStorage`. Из неё приложение стартует
мгновенно и продолжает работать без сети. Правки, сделанные офлайн, копятся в
очереди и уезжают сами, когда связь возвращается — индикатор в шапке показывает,
что происходит.

**Чужие изменения** прилетают по вебсокету, без опроса: второй человек добавил
блюдо — оно появилось, ничего нажимать не нужно.

**Конфликты.** Если двое одновременно правят одно и то же блюдо, побеждает тот,
кто сохранил последним. Для картотеки это осознанный размен: настоящее слияние
по полям стоит сильно дороже, чем приносит пользы.

## Локальный режим

Если `config.js` пустой, приложение запускается без базы: всё работает, но
список живёт только в этом браузере. Удобно, чтобы посмотреть до всякой настройки —
достаточно открыть `index.html` через любой локальный сервер:

```bash
python3 -m http.server 8080
# затем http://localhost:8080
```

Просто двойным кликом по файлу не откроется: браузер запрещает модулям
загружаться с `file://`.

## Если что-то не так

**«Не получилось: Failed to fetch»** — не тот `SUPABASE_URL` либо проект
в Supabase уснул. Бесплатные проекты засыпают после недели без обращений:
зайти в панель и нажать **Resume project**, данные при этом целы.

**После регистрации просит подтвердить почту** — не выключено подтверждение,
см. шаг 3.

**Второй человек не видит блюд** — он ввёл код и попал в свою кухню, а не в твою.
Проверить: во вкладке «Блюда» внизу написано название кухни. Должно совпадать.

**Изменения не прилетают сами, только после перезагрузки** — в схеме не
отработал блок про realtime. Выполнить в SQL Editor:
```sql
alter publication supabase_realtime add table public.dishes;
alter publication supabase_realtime add table public.cook_log;
```

**Обновил файлы, а в браузере старая версия** — виноват service worker.
Обновить страницу с `Ctrl+Shift+R` (на телефоне — закрыть и открыть вкладку заново).

## Что где лежит

```
index.html              разметка всех экранов
styles.css              оформление
app.js                  вся логика: свайпы, фильтры, синхронизация
config.js               ← сюда вставить адрес и ключ Supabase
supabase/schema.sql     таблицы и правила доступа
manifest.webmanifest    чтобы ставилось на домашний экран
sw.js                   чтобы открывалось без сети
icons/                  иконки приложения
```

Сборки нет: что лежит в репозитории, то и работает в браузере.
