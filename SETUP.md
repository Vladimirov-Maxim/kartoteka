# Как это устроено и как поднять свою копию

## Устройство

Своего сервера нет. Есть два бесплатных кусочка чужой инфраструктуры:

```
GitHub Pages  ──отдаёт──▶  index.html  ──запросы──▶  Supabase
   (файлы)                 (в браузере)              (данные)
```

- **Страница** — статика без сборки: `index.html`, `styles.css`, `app.js`.
  Что лежит в репозитории, то и работает в браузере.
- **Данные** — Postgres в Supabase. API он генерирует сам из таблиц,
  писать его не надо.
- **Фильтры, поиск, колода** считаются в браузере: при открытии список
  загружается целиком и дальше работает без запросов, в том числе без сети.

### Таблицы

- `kitchens` — общее пространство и код приглашения
- `members` — кто в нём состоит
- `dishes` — блюда, состав хранится структурно (`{name, qty, unit}`)
- `cook_log` — журнал готовки, одна строка на каждое нажатие «Готовить»
- `shopping_items` — список покупок

Журнал сделан отдельной таблицей не просто так. Если хранить у блюда счётчик,
двое, нажавшие «Готовить» одновременно, затрут отметку друг друга. В журнал строки
только добавляются, поэтому конфликтовать нечему, а «когда готовили последний раз»
и «сколько раз всего» считаются из него на лету.

### Доступ

Вся защита — в правилах внутри Postgres: строку видно, только если ты состоишь
в той же кухне. Проверка живёт в базе, а не в коде страницы, поэтому её нельзя
обойти, поправив JS в браузере.

Публичный ключ в `config.js` лежит открыто по замыслу — сам по себе он не даёт
доступа к данным. А вот ключ `service_role` (он же Secret key) обходит все правила:
в репозиторий он попасть не должен никогда, и приложению он не нужен.

### Синхронизация

Правка сразу меняется на экране, уходит в базу и прилетает второму устройству
по вебсокету. Локальная копия в браузере работает как кэш и как очередь для правок,
сделанных без сети. При возвращении к приложению база перечитывается — на случай,
если телефон проспал события, пока экран был погашен.

Конфликты: если двое одновременно правят одно блюдо, побеждает сохранивший последним.
Для картотеки это осознанный размен — слияние по полям стоит дороже, чем приносит.

## Поднять свою копию

### 1. Проект в Supabase

Зайти на [supabase.com](https://supabase.com), **New project**, дождаться, пока
поднимется. В настройках безопасности при создании оставить **Enable Data API**
и **Automatically expose new tables** включёнными.

### 2. Схема

SQL Editor → **New query** → выполнить по очереди, каждый файл целиком:

```
supabase/schema.sql                      таблицы, правила доступа, вход по коду
supabase/migration-001-ingredients.sql   состав как структура, а не строка
supabase/migration-002-shopping.sql      список покупок
supabase/migration-003-deletes.sql       чтобы удаления доходили до второго устройства
```

Каждый должен ответить `Success. No rows returned`. Запускать повторно безопасно.

### 3. Аккаунты

Authentication → **Sign In / Providers** → Email: выключить **Confirm email**,
иначе регистрация пойдёт через письмо.

Если хочется закрыть вход посторонним — там же выключить **Allow new users to sign up**,
а людей заводить руками: Authentication → Users → **Add user** → Create new user
с галочкой **Auto Confirm User**.

### 4. Ключи

Project Settings → **API Keys**. Скопировать **Project URL** и **Publishable key**
(прежнее название — anon public) в `config.js`.

### 5. Выкладка

Создать пустой публичный репозиторий и запушить:

```bash
git remote add origin https://github.com/ИМЯ/kartoteka.git
git push -u origin main
```

Затем Settings → **Pages** → Source: **Deploy from a branch** → `main`, папка `/ (root)`.

На бесплатном тарифе Pages работает только из публичного репозитория. Секретов
в коде нет, так что это нормально. Нужен приватный — тот же набор файлов без
изменений разворачивается на Cloudflare Pages или Netlify.

### 6. Кухня

Открыть ссылку, зарегистрироваться, нажать **Создать кухню**. Код приглашения
появится во вкладке «Блюда» — второй человек вводит его при первом входе.

## Локальный режим

Если `config.js` пустой, приложение запускается без базы: всё работает, но список
живёт только в этом браузере. Удобно посмотреть до всякой настройки:

```bash
python3 -m http.server 8080
# затем http://localhost:8080
```

Двойным кликом по файлу не откроется — браузер запрещает модулям загружаться
с `file://`.

## Если что-то не так

**«Failed to fetch»** — не тот `SUPABASE_URL` либо проект уснул. Бесплатные проекты
Supabase засыпают после недели без обращений: зайти в панель и нажать **Resume project**,
данные при этом целы.

**Второй человек не видит блюд** — он попал в свою кухню, а не в твою. Во вкладке
«Блюда» внизу написано её название, оно должно совпадать.

**Изменения не прилетают сами** — не отработал блок про realtime. Выполнить:

```sql
alter publication supabase_realtime add table public.dishes;
alter publication supabase_realtime add table public.cook_log;
alter publication supabase_realtime add table public.shopping_items;
```

**Удаления не доходят до второго устройства** — не применилась миграция 003.

**После выкладки в браузере старая версия** — `Ctrl+Shift+R`. Один раз после
обновления service worker может отдать прошлую копию; дальше подхватывается само.

## Что где лежит

```
index.html              разметка всех экранов
styles.css              оформление, палитра в самом начале
app.js                  вся логика: свайпы, фильтры, покупки, синхронизация
config.js               адрес проекта и публичный ключ Supabase
supabase/               схема и миграции
manifest.webmanifest    чтобы ставилось на домашний экран
sw.js                   чтобы открывалось без сети
icons/                  иконки приложения
```
